# 四项后端优化验收（2026-10-10）

本次保持现有 Python 服务、模型网关和运行依赖，完成职责拆分、统一数据结构、共享证据、逐组返回。README 和完整架构文档按用户要求暂缓编写。

## 实现

- `server.py` 只负责 HTTP、静态文件、媒体访问与流式事件；`pipeline.py` 编排获取和生成；`sources.py` 路由平台；`vision.py` 共享读图；`recipes.py` 校验菜谱和计算购物用量。
- `contracts.py` 定义来源、证据、食材、菜谱和生成结果；平台提取结果在流程入口统一转换。
- 接口只发送一次证据列表，菜谱使用 `evidenceIds` 引用；本地存储与备份使用 version 2 的共享证据结构，兼容旧菜谱数组。单道菜的连续片段保留完整上下文，只有明确独立菜谱继续分组并行。
- `Accept: application/x-ndjson` 开启逐组返回。每组校验通过后立即显示和保存，结束事件不重发菜谱。普通 JSON 接口继续可用，返回 schemaVersion 2。
- 重试同一次未完成生成时，复用成功组缓存并避免再次添加已收到卡片。编辑后的菜名、份数和选择状态不会被后续组覆盖。前端重试去重记录保存在当前页面内；重新加载页面后不保证重试去重，已保存菜谱仍保留。
- 修复实际发现的网关凭证刷新竞争：仅针对本地网关明确返回的 `No healthy provider found` HTTP 500，最多请求三次，间隔 1 秒、2 秒。其他错误直接报告。
