# 后端开发进度

更新时间：2026-10-12

目标：保留当前移动网页，将家庭业务规则放到服务端，建立可迁移的数据模型，随后接入本地留档、持久化 AI 任务和阿里云部署。

## 阶段与验收

| 阶段 | 状态 | 验收目标 |
|---|---|---|
| P1 服务端业务规则及现有客户端接入 | 已完成 | 服务器计算库存、预留、撤销、完成和取消；拒绝旧版整份覆盖；重复请求只生效一次；保留已有家庭数据 |
| P2 正式运行基础 | 本机及 CI 验收通过 | FastAPI、PostgreSQL、数据库迁移、配置、备份与恢复；迁移现有账号和家庭 |
| P3 客户端本地留档 | 本机验收通过 | IndexedDB 菜谱与记录副本、草稿、同步状态、断网查看；共享库存和本餐写入联网确认 |
| P4 文件与 AI 任务 | 本机验收通过 | 独立图片上传、家庭权限、任务持久化、关页面可恢复、失败重试；图片/文字/现有食材生成 |
| P5 部署准备与验证 | 部署配置及 CI 容器验收通过；实际阿里云部署待目标 | HTTPS、独立 API/worker/PostgreSQL、持久卷、日志、额度和用量记录；公网和两台真实手机另行验收 |
| P6 移动 App | 安卓模拟器流程通过；远程 iOS 模拟器构建启动通过 | 安卓调试 APK 安装及联网/离线验证；iOS 模拟器 .app，真机签名尚未配置 |

第一轮先复用现有 SQLite 和账号会话，不在同一次改动中替换数据库、HTTP 框架和库存算法。P1 的实体及操作协议用于后续 PostgreSQL 迁移；完成 P1 不代表完整后端或商业上线已经完成。

## 本轮记录

- 开始：核对 PRD、账号共享实现与库存计算。旧版以客户端计算后的整份家庭快照作为写入，不能作为正式库存记账接口。
- 计划：增加家庭实体存储、旧快照自动迁移、服务端操作接口、幂等操作记录；客户端等待服务器确认后展示成功。
- 完成：新增 kitchen_service.py 服务端规则、kitchen_storage.py 实体适配器及 `/api/household/commands`。库存、预留、撤销、取消、完成与菜谱编辑由服务器计算校验，旧整份覆盖接口停用。
- 完成：业务写入、版本与回执事务提交；同编号重试只执行一次，过期版本/餐次拒绝覆盖。客户端发送前持久保存回执，响应丢失可同编号恢复，未确认时阻止继续修改。
- 完成：现有移动网页全部共享写入接入操作协议，未登录体验继续本地运行；多批流式菜谱逐批等待保存，来源证据保持完整。
- 验收：62 项 JavaScript 检查、75 项 Python 检查；包括双账号并发、重复请求、完成不重复扣减、回执跨重启、旧快照迁移、无效输入和家庭隔离。
- 浏览器验收：两个独立账号注册、邀请入同家庭、一方点菜另一方锁定、锁定点击反馈、补录 500 克并完成。原有 500 + 补录 500 − 本餐 300 = 剩余 700 克，仅保存一条餐次记录。
- 流式验收：使用隔离 HTTP 测试材料返回三批菜谱，三张均保存且证据齐全；此次未调用真实 AI。浏览器控制台无错误。
- 迁移准备：使用 SQLite 在线备份复制现有本机账号库，副本完整性检查 ok；当前库内 0 个家庭。已有预留餐次的迁移以自动化样本验证，原快照不被改写。
- 适配器限制：当前仍为 SQLite、实体 JSON 和家庭行集重写；P2 才做 PostgreSQL 字段、局部更新与正式服务框架。接口说明见 [backend-api.md](backend-api.md)。
